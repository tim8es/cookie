# F1 Appearance codec subprocess containment

Refs #223 and #289. The server adapter entrypoint now routes image normalization to one fixed, short-lived Node process. Native sharp/libvips is loaded only by the worker. The parent and child independently enforce input size; the parent stops on output overflow and verifies the bounded binary dimensions/PNG header. The child is terminated at a 10-second wall-clock deadline (including startup), native decoder timeout 5 seconds, one codec admission per parent, heap cap 64 MiB and one libvips/UV worker, no persistent cache. Admission is released only after child close, never after merely sending a kill signal. No arbitrary client path, shell, inherited application environment or error output.

This isolates ordinary native crashes/hangs from the API event loop. On **POSIX only**, the codec process is now started as the leader of its own process group. The supervisor sends SIGKILL to the entire group on timeout, fatal transport failure, and after the leader's stream close (including a nominally successful response); a direct-child fallback handles unavailable group signalling. This prevents ordinary non-detached descendants in the codec's process group from continuing after the codec attempt. Real short-lived grandchild tests verify this both after a valid output and after a timeout. **Windows still kills only the direct child**; no Windows process-tree containment claim is made.

**Not a security sandbox or a release approval.** The child and its in-group descendants still run with the same OS user, filesystem and network privileges; V8 heap and pixel limits do not cap native RSS. A malicious child can escape the process group by starting a new session/process group; an unkillable OS process can still hold admission. This mitigation is not cgroups, namespaces, seccomp, AppArmor/SELinux, a network deny policy, an independent runtime or an OS-level privilege boundary. Linux/Altare staging upload remains blocked until the deployment demonstrates enforceable CPU/native-memory/privilege/network containment and ingress resource/time limits, audited multi-instance concurrency, a separate security review and real compiled browser proof. **Do not mount upload from this PR.**

Source tests run real child processes: real JPEG conversion, valid result, invalid raster, concurrent admission, deadline, nonzero exit, malformed or oversized output and secret environment exclusion. Additional **POSIX process-group** regressions spawn actual in-group grandchildren with ignored stdio and synthetic file sentinels; they must not survive successful response or supervisor timeout. These tests are not substitutes for an adversarial OS sandbox proof. Compiled worker path is relative to the built adapter; actual compiled runtime exercise and Windows/Altare isolation proof remain follow-up gates. No new migration or deployment.
