# F1 Appearance codec subprocess containment

Refs #223 and #289. The server adapter entrypoint now routes image normalization to one fixed, short-lived Node process. Native sharp/libvips is loaded only by the worker. The parent and child independently enforce input size; the parent stops on output overflow and verifies the bounded binary dimensions/PNG header. The child is terminated at a 10-second wall-clock deadline (including startup), native decoder timeout 5 seconds, one codec admission per parent, heap cap 64 MiB and one libvips/UV worker, no persistent cache. Admission is released only after child close, never after merely sending a kill signal. No arbitrary client path, shell, inherited application environment or error output.

This isolates ordinary native crashes/hangs from the API event loop. It is NOT a security sandbox: the child runs with the same OS user/filesystem/network permissions and native RSS is not controlled by V8 heap or pixel limits. An unkillable OS process can still hold admission; process descendants or compromised native code are not contained by this mechanism. Production/staging ingress must still use independently enforceable memory/CPU and privilege/network controls, plus bounded HTTP concurrency, tenant storage quotas and security review. Do not mount upload from this PR.

Source tests run real child processes: real JPEG conversion, valid result, invalid raster, concurrent admission, deadline, nonzero exit, malformed or oversized output and secret environment exclusion. Compiled worker path is relative to the built adapter; actual compiled runtime exercise and Windows/Altare proof remain follow-up gates. No new migration or deployment.
