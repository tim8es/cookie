# Публичная ссылка записи — контракт F1 (PROPOSED)

Issue [#222](https://github.com/tim8es/cookie/issues/222), REQ-004/024, ADR-0005; зависит от #309, #223, #113/#165 и release gate #203. Это предложение для технического review, не изменение ACCEPTED baseline и не разрешение публичного запуска.

## 1. Scope и идентификатор

Предлагаемый путь `/book/{salonSlug}` в общей web-оболочке; F1 — явно опубликованная пара Organization + Location (одна точка для первого технического среза). Для F2 потребуется самостоятельная ссылка филиала. Slug — публичный locator, не секрет, не bearer и не подтверждение прав. Не принимать произвольный tenantId/locationId как замену разрешению ссылки. Точные правила выдачи, изменения, повторного использования slug и canonical redirects — открыты до review. Не включать автоматическую публикацию при регистрации.

## 2. Предлагаемые границы API

| Операция | Доступ и результат |
| --- | --- |
| Resolve slug + catalog | Анонимный read только явно опубликованного и разрешенного scope: название салона, опубликованное оформление, доступные услуги с ценой/длительностью, публичные отображаемые имена мастеров и филиал. Без приватных профилей, контактов, графиков владельца, Customer/Booking ID. |
| Slots | Повторно разрешить тот же опубликованный scope на сервере; проверить service/staff/location assignment и entitlement; использовать существующий Scheduling/Booking availability. Не выдавать занятые записи или причину занятости. Ограниченный диапазон/ответ; лимиты подлежат review. |
| Login | Выбор услуги/мастера/времени может быть локальным неавторитетным черновиком. Верификация Identity через разрешенный провайдер #309; никакой выдачи полномочий на основании slug или введенного контакта. После login заново разрешить scope и перечитать слот/цену. |
| CreateBooking | Только проверенная Identity и customer ownership в рамках разрешенного scope, актуальная server quote и idempotency key. Использовать существующий транзакционный Booking Engine; успешный ответ только после подтвержденного commit. Никакой анонимной записи или параллельного движка. |
| Owner publication | Защищенная owner-команда с транзакционной проверкой полномочий и явной публикацией/отзывом. Ссылка доступна для копирования только после настоящей публикации и готовности полного клиентского пути. |

Предлагается выделить read adapter для публичных DTO, не переиспользовать защищенные owner endpoints и не ослаблять staging customer permission. До согласования схемы, guest proof и полного релизного gate ни один новый anonymous API не регистрируется в runtime.

## 3. Статусы и безопасность

- Пока resolver отсутствует, точное семейство `/book` и `/book/*` возвращает HTML 404 с текущей unavailable-страницей, no-store/noindex; `/booking` остается защищенной навигацией Workspace.
- После реализации resolver: неизвестный, неопубликованный, отозванный или недоступный по entitlement slug — одинаковый публичный unavailable/404 без раскрытия причины; сбой инфраструктуры — 503, не фиктивное подтверждение. Изменение слота — 409 с повторным чтением. HTTP 200 каталога не означает успешную запись.
- Отзыв публикации, изменение assignment и истечение entitlement проверяются на сервере повторно при записи. Согласовать транзакционные блокировки с существующими #113/#165. Не расширять права старых бронирований и не вводить новые бизнес-политики #285.
- Не помещать токены, ПДн или доказательство владения в URL, analytics или логи. Ограничить размер запросов и выдачи; CORS/embed/WebView и abuse/rate limiting требуют отдельного security review.

## 4. Порядок реализации

1. Review контракта locator/publication, DTO и guest/customer proof; закрепить precise route и lifecycle.
2. Изолированный persistence + resolver + positive/negative PG16/17 tests на двух synthetic tenants. Runtime fail-closed до явного staging gate.
3. Реальный read catalog/slots и отдельная shared Booking UI оболочка; прямое открытие и reload в чистом браузере, mobile. Не выдавать ссылку как рабочую до готовности записи.
4. Login handoff с сохранением только неавторитетного выбора, повторная валидация, Confirmed CreateBooking. Проверить owner calendar после restart, 409 при двух конкурентных клиентах и отсутствие доступа к B через A.
5. Exact-head CI, независимое security review, local/private Altare evidence; отдельные разрешения на реальные ПДн, публичный пилот и production.

## 5. Не подтверждено

Slug persistence/resolution, publication lifecycle, anonymous catalog, verified guest/customer path и second-browser Confirmed booking еще не реализованы этим PR. Ни один коммерческий default или конечный URL не утверждается. Реальные данные и публичное включение запрещены до отдельного согласования.
