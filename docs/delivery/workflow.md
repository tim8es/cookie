# Правила планирования, задач и принятия решений

**Статус: PROPOSED** для процесса работы в cookie.

## Система учёта
- GitHub Issues — задачи и эпики.
- Документы в docs — источник требований, рисков, контрактов и решений.
- PR — единица review изменений и доказательств тестирования.
- Roadmap связывает фазы и задачи. Не плодить issue на каждый UI-клик или отдельную функцию внутреннего метода.

## Номенклатура
Префиксы Issue: [EPIC], [DOC], [ARCH], [UX], [ENG], [OPS], [GTM]. Приоритет в title: P0 блокирует следующую фазу, P1 важен для первого коммерческого релиза, P2 расширение, P3 идеи/исследование. Фаза: F0 docs, F1 technical slice, F2 sellable, F3 growth.

## Статусы
Backlog -> Ready (REQ + AC + deps) -> In progress -> Review -> Done. Blocked фиксируется в Issue с причиной. Предлагаемые теги, если GitHub labels не настроены, читаются в теле и названии задач.

## Definition of Ready
Детальное ожидаемое поведение, область ответственности, link на документы/REQ/ADR, критерии приёмки, зависимости, не-сценарии/ограничения. Не нужно писать низкоуровневые TODO до начала coding.

## Definition of Done — docs
Текст полный, непротиворечивый, соседние документы согласованы; сохранён реестр решений; все открытые блокирующие вопросы представлены Issue; PR просмотрен человеком и влит.

## Definition of Done — code
См. ../quality/test-strategy.md

## Review cadence
В F0 первая ревизия по PR, затем consistency audit: требования -> ADR -> модули -> roadmap -> Issues. После принятия docs freeze можно начать F1. ADR менять через новый ADR или update с историей/ссылкой на Issue.

## Приоритизация
P0: критический путь и блокеры архитектуры/безопасности. P1: продаваемый UX и расширения, обещанные первой коммерческой версии. P2: важная функциональность после проверки спроса. P3: идеи без доказанной ценности. Приоритет не равен очереди выполнения: зависимости определяют порядок.

## Как работать с агентами
AGENTS.md содержит правила проекта; никаких пушей в main без PR; отсутствие самовольного выбора стека/изменения ADR; не писать production code до явной команды пользователя о старте разработки.
