# F1 private staging customer catalog and available times

Depends on #257 (trusted staging client identity) and #249 (canonical staging availability). Adds a client-only `staging.customer.offers.read` capability; migration only extends active dedicated synthetic client roles with the intact context permission. Both permissions and exact bound session must be checked in one PostgreSQL transaction. No owner permission or client input Customer ID is accepted. Client-specific GET staging-customer-offers and GET staging-customer-slots mounted only with staging flag; current live publication grant and exact active placement required. Empty catalog without a valid grant, 409 for unavailable placement. No actual booking mutation/quote or reservation. Catalog projects only approved display names, identifiers, duration, time zone and base price; slot DTO excludes occupied-until/other booking data. Uses existing availability algorithm, 15-minute preview grid and confirmed occupancy across branches. Bounded reads fail closed above 200 placements. Separate frontend selection of branch, service, staff and date; stale requests suppressed, auth failure clears displayed account data, browser expiry timer removes session. A selected time is explicitly not a reservation. No customer PII, public API, paid entitlement, production or Altare deployment. #113/#165/#255 security and integration gates remain separate. No final price/snapshot until atomic booking command. PG and compiled Chromium checks use only synthetic credentials.
