# Controlled staging availability (F1 #203)

Stacked on independently tested #245 shift publication; no duplicated mutation code. The protected owner GET staging-availability uses a current explicit grant, exact grant-bound Staff/Location/Service receipt, active assignment/profile/service and a single database snapshot. It reuses listAvailableSlots, filters past starts, reads same-location shifts/blocks and tenant-wide Confirmed occupancy (including buffer). Local-date/IANA-zone and original shift-grid alignment are preserved. The bounded interval reads fail closed above 200 per input source. The 15-minute grid is a staging display choice, not a commercial booking policy. No slots are reserved and no customer Booking route is started. Owner-only permission and staging flag required; no implicit grant. UI displays server results for one selected date and authorized placement. Browser test uses compiled API + disposable database and synthetic Telegram proof. Integration test injects synthetic confirmed booking and break fixtures, not actual customer traffic. No public access, production, trial/paid policy or actual deployment. Reconcile with #242/#247 and #245 before merge.
