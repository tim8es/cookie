# F1 — редактирование черновика услуги (#20, REQ-001/034)
Предыдущий срез позволял только создать услугу. Новый защищённый PATCH /v1/organizations/:tenantId/services/:serviceId принимает название, длительность, базовую цену (целые копейки), expectedRevision, обязательный Idempotency-Key. Владелец редактирует существующую услугу, ID/назначения сохраняются. Не допускаются изменение active/status, чужая организация, отсутствующий ресурс, активная услуга, активное назначение или любая история Booking. Допускаются только API-originated create drafts. Требуется актуальное permission catalog.service.edit-draft; транзакция держит policy/session locks, advisory replay key и SQL row lock. Первоначальная квитанция создания и квитанции изменения — immutable snapshots, GET выдаёт актуальную запись. Устаревшая версия 409, одинаковый ключ+payload возвращает исходный результат, иной payload 409.
 
Migration 0031 adds draft_revision, receipts and bootstrap/backfill permission. Existing create receipts are backfilled from currently stored source rows; past external SQL changes cannot be reconstructed. DTO revision is required for both GET and POST. Activate/publish workflows must share the service row lock and permanently track prior publication before enabling service reactivation or archive/edit. This slice does not claim safe editing for historical published services. No public availability, real entitlement, billing, or pilot deployment. Existing #35 trial/paid capacity is not implemented; do not bypass.
 
UI uses actual persisted data, edit/cancel, input disabled during request, explicit stale revision error, and same-key retry after uncertain response while the page is open. Supports exact two-decimal RUB input/display without changing final Booking rounding policy. Receipt is not current state: refetch after mutation. Draft-only.

Integration preserves #228 tenant capacity check after replay lookup and its concurrent last-slot regression. Includes combined real owner browser harness (Overview, Location, Staff, ShiftPlan, draft edit, restart and local expiry); no live customer Booking or Altare deployment proof.
