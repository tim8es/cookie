# F1 client booking attempt: uncertain outcome safety

Refs #23 #66 #203 #165. Current main has a reusable BookingAttempt state machine, but no public customer write route. A lost response followed by denied or conflicting retry is not proof of failure. Keep the original attempt unresolved and disallow a new attempt until reconciliation. Verified Confirmed receipt resolves uncertainty; normal first-attempt verified conflict still refreshes availability. A generic exception/HTTP failure is not treated as proof of rollback. Receipt validator checks exact canonical UTC minute, request start, confirmed status, ID, interval ordering and exact nonnegative PostgreSQL bigint price. This validator is a proposed integration building block, not a public DTO approval. No booking route, mock substitute, storage of tokens or deployment is introduced. Recovery across reload/session loss and customer write authorization are separate mandatory integration work.
