# Развёртывание, эксплуатация, self-hosting

**Статус: PROPOSED.** Не начинаем production на бесплатном хостинге без проверки SLA, коммерческих условий и локализации ПДн.

## Модели
### SaaS
Общий release, строгое разграничение tenants. Обновления/миграции централизованы, админские доступы ограничены. Доступность платных расширений регулируется entitlements; disabled add-on не удаляет бизнес-данные.

### Self-hosted
Versioned image/manifest + Docker Compose, persistent Postgres volume, reverse proxy/TLS, secrets/env, миграции, backups. После инсталляции веб-онбординг без ручного редактирования БД. Должна быть возможность работать при временной недоступности сервера лицензирования (с политикой grace periods) — подробнее договориться после выбора лицензии.

### Демо
Разрешён синтетический dataset и disposable окружение, включая Altare при соблюдении условий. Ни один настоящий клиентский телефон, запись, ФИО или токен в таком окружении по умолчанию.

## Операционные гарантии
- Health probes и startup checks модулей; rollback версий и миграций.
- Периодические бэкапы с мониторингом, тест восстановления, сохранение вне primary VM.
- HTTP API без состояния, worker с безопасными retries/idempotency.
- SLO и RPO/RTO до коммерческого запуска после нагрузки/стоимости; не объявлять цифры без теста.
- Release notes, список миграций, матрица совместимости kernel/modules.
- Два типа обновлений: SaaS авто, self-hosted по выбранному соглашению.

## 10–15 минут до первой записи
Целевой поток: создать организацию, базовые рабочие часы, услуга/цена/длительность, сотрудник, ссылка записи, тестовая бронь. Для self-hosted это время относится к **онбордингу после готовой инфраструктуры**, а не к покупке сервера, DNS и TLS.

## Коммерческие ограничения
- Лицензионная модель с исходниками требует ясного определения прав на код и обновления.
- Исключительные права на платформу не передаются с обычной установкой.
- Стоимость SLA, поддержки, SMS, LLM и внешних модулей отдельно учитывается в экономике.
- План migration/export вне поставщика и offboarding необходим как дифференциатор.

## Коммерческий пилот и договорные ограничения (ACCEPTED product / PROPOSED delivery)
- **DEC-113 / REQ-067:** первым салонам согласовываются индивидуальные коммерческие предложения **до успешной регистрации Organization** и старта бесплатного теста. Единый публичный прайс откладывается до проверки спроса. Предложение для конкретной организации должно описывать срок, набор функций, цену и период paid continuation.
- **DEC-099/101/103/105:** 30 календарных дней с регистрации, затем без добровольной оплаты создание новых бронирований блокируется; существующие Confirmed доступны для обслуживания/разрешённого управления и экспорта. Предварительное коммерческое согласование не даёт согласия на автоматические списания.
- **DEC-107/109/111:** платные tiers по числу уникальных действующих bookable мастеров без ограничения количества Booking; дополнительного мастера можно завести в справочник, активация сверх capacity — после добровольного upgrade.
- **OPEN before real pilot:** документы/договор, действующий способ оплаты и фискальные обязательства, локализация ПДн, доступ/экспорт/retention при долгом отказе, безопасная доставка уже согласованных уведомлений и технико-операционные гарантии. **PROPOSED DEC-114:** журнал вручения индивидуального оффера до регистрации, versioning и отдельный paid opt-in. Не выдавать разработанный документ за юридическое согласование.

## Размещать реальные ПДн в РФ
Провайдер и регион хранилища выбираются с проверкой локализации и договоров. Не считать free Altare продакшн-решением для РФ; сначала правовая оценка и письменное согласование коммерческого использования.
